## Routes contract

All responses are JSON. Identifiers are strings or integers (your choice, but consistent). Extra fields are allowed
and ignored. Sessions and goals can be created, read, updated and deleted; the profile is unique (read and update);
the assessment result is created and read from the profile.

| Method | Path | Request body | Response (success) | Errors |
|---|---|---|---|---|
| GET | `/api/profile` | — | 200 `{name, bio, preferences, assessmentResult}` (strings; `assessmentResult` empty or `null` if the assessment is not done) | — |
| PUT | `/api/profile` | `{name, bio?, preferences?}` | 200 updated profile | 400 if `name` is missing or empty |
| POST | `/api/assessment` | `{answers: [...]}` (non-empty list, content chosen by the site) | 201 `{assessmentResult}` non-empty string; the same value appears in `GET /api/profile` | 400 if `answers` is missing, not a list or empty |
| GET | `/api/coaches?q=text` | — (`q` optional) | 200 `[{id, name, specialty}]`, at least 3 without `q`; with `q` only the coaches whose `name` or `specialty` contains `q` (case-insensitive) | — |
| GET | `/api/sessions` | — | 200 `[{id, coachId, datetime, status}]` | — |
| POST | `/api/sessions` | `{coachId, datetime}` (`datetime` ISO 8601, e.g. `2026-12-01T10:00`) | 201 `{id, coachId, datetime, status: "confirmed"}` | 400 if `coachId` does not exist or `datetime` is missing or not a valid date |
| PATCH | `/api/sessions/:id` | `{datetime}` | 200 updated session | 400 if `datetime` is not valid; 404 if `id` does not exist |
| DELETE | `/api/sessions/:id` | — | 204 | 404 if `id` does not exist |
| GET | `/api/goals` | — | 200 `[{id, title, progress}]` | — |
| POST | `/api/goals` | `{title, progress?}` | 201 `{id, title, progress}` (`progress` defaults to 0) | 400 if `title` is missing or empty, or `progress` is not an integer in 0-100 |
| PATCH | `/api/goals/:id` | `{progress?, title?}` | 200 updated goal | 400 if `progress` is not an integer in 0-100 or `title` is empty; 404 if `id` does not exist |
| DELETE | `/api/goals/:id` | — | 204 | 404 if `id` does not exist |

**Persistence:** profile, assessment result, sessions and goals in a JSON file (`data/db.json`) or SQLite
(`data/app.db`) in the workspace; the preloaded coaches may live in the code or in the same store. Everything must
survive a restart of `start.sh`.

## data-testid markers

| Marker | Element |
|---|---|
| `assessment-option` | the **first** answer option of **each** assessment question (radio or button): one per question |
| `assessment-submit` | button that submits the assessment |
| `assessment-result` | text of the assessment result; it appears after submitting and stays visible (in the profile) after a reload |
| `profile-name` | text field for the name in the profile form |
| `profile-save` | button that saves the profile |
| `coach-search` | search field for coaches (filters by name or specialty) |
| `coach-card` | card of a coach in the list (one per visible coach); contains the name; clicking it selects the coach for booking |
| `session-datetime` | `<input type="datetime-local">` of the booking form |
| `session-submit` | button that confirms the booking with the selected coach |
| `goal-title` | title field of the new goal |
| `goal-add` | button that creates the goal |
| `goal-progress` | `<input type="number">` 0-100 inside every goal of the list; the value is saved on change (`change` event) or with Enter |

## Notes

- **Single page:** all the markers are on the page `/` and visible without clicking any navigation (sections one
  below the other; anchors and scrolling are fine, hidden tabs are not).
- `goal-progress` is a number field, not a slider (`range`), and has no save button.
- The search in `coach-search` applies while typing or with Enter.
