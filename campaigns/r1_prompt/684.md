## Routes contract

Format: JSON with `Content-Type: application/json`, except the upload (`multipart/form-data`) and the file content
(raw bytes). File object:

```json
{"id": "<string or integer, unique>", "name": "notes.txt", "size": 4, "tags": ["work", "important"]}
```

`tags` is a list without duplicates, in any order. A tag is a string that is non-empty after trimming leading and
trailing spaces; the server stores it trimmed. Upper and lower case are distinct (`Work` != `work`).

| Method | Path | Request body | Response (success) | Errors |
|---|---|---|---|---|
| POST | `/api/files` | multipart, field `file` (one file) | `201`, file object with `name` = original name, `size` in bytes, `tags: []` | `400` if the `file` field is missing |
| GET | `/api/files` | - | `200`, list of file objects (possibly `[]`) | - |
| GET | `/api/files?tag=<tag>` | - | `200`, only the files with that tag (exact match) | - |
| GET | `/api/files/{id}` | - | `200`, file object | `404` unknown id |
| GET | `/api/files/{id}/content` | - | `200`, bytes identical to the uploaded ones | `404` unknown id |
| PUT | `/api/files/{id}/tags` | `{"tags": ["work", "important"]}` (replaces the whole list; `[]` removes all tags) | `200`, updated file object, duplicates removed | `400` if `tags` is missing, not a list, or contains a non-string or empty element; `404` unknown id |
| DELETE | `/api/files/{id}` | - | `204` without body; file and metadata removed | `404` unknown id |

**Persistence:** metadata in `data/files.json` or `data/app.db` (SQLite) in the workspace; file contents in
`data/uploads/`. Everything survives a restart of `start.sh`. File names inside `data/uploads/` and the internal
structure of the server are up to you.

## data-testid markers

| Marker | Element |
|---|---|
| `upload-input` | the `<input type="file">` used to choose the file |
| `upload-submit` | the button that uploads the chosen file |
| `file-item` | container of a file in the list (one per file) |
| `file-name` | inside each `file-item`: the file name; text = exact original name |
| `file-delete` | inside each `file-item`: control that deletes that file |
| `tag-input` | inside each `file-item`: text field for a new tag |
| `tag-add` | inside each `file-item`: button that adds the tag written in `tag-input` |
| `file-tag` | inside the `file-item`: each tag of the file; text = tag name (see `tag-remove`) |
| `tag-remove` | inside each `file-tag`: control that removes that tag from the file |
| `filter-tag` | one filter control for each existing tag; text = tag name |
| `filter-clear` | control that removes the filter and shows all files |

## Notes

- The text of a `file-tag`, after removing the text of its `tag-remove` and surrounding spaces, must be exactly the
  tag name (so a `×` inside the pill is fine).
- Filtering is by one tag at a time; the `filter-tag` controls follow the existing tags without reloading the page.
