## Routes contract

Prefix `/api`, request and response bodies in JSON. Prices are numbers (monthly price in euros).

| Method | Path | Request body | Response | Errors |
|---|---|---|---|---|
| GET | `/api/plans` | — | `200` `[{"id": str, "name": str, "monthlyPrice": number, "dataGb": number}]` (at least 3 plans) | — |
| GET | `/api/plans/{id}` | — | `200` `{"id": str, "name": str, "monthlyPrice": number, "dataGb": number, "features": [str], "benefits": [str]}` (`features` and `benefits` non-empty) | `404` unknown id |
| GET | `/api/account` | — | `200` `{"name": str, "email": str, "phone": str}` | — |
| PUT | `/api/account` | `{"name": str, "email": str, "phone": str}` (`phone` optional) | `200` the updated account | `400` if `name` is missing or empty, or `email` does not contain `@` |
| GET | `/api/support/messages` | — | `200` `[{"id": str, "text": str, "reply": str}]` in sending order | — |
| POST | `/api/support/messages` | `{"text": str}` | `201` `{"id": str, "text": str, "reply": str}` with a non-empty `reply` (an automatic answer, or a confirmation that an agent will assist shortly) | `400` if `text` is missing or empty |

**Persistence:** account and support messages in a JSON file (`data/db.json`) or SQLite (`data/app.db`) in the
workspace; they survive a restart of `start.sh`. The plans may be static in the code.

## data-testid markers

| Marker | Element |
|---|---|
| `site-nav` | the navigation bar, visible on every page (container of the `nav-link-<section>` links) |
| `nav-link-<section>` | link of the navigation bar, one per section: `nav-link-plans`, `nav-link-support`, `nav-link-account` |
| `plan-card` | card of a plan in the list (one per plan); clicking it opens the plan page |
| `plan-detail` | container of the plan page, with name, features, benefits and price |
| `support-open` | button on the home page that opens the customer support chat |
| `support-input` | text field of the chat |
| `support-send` | button that sends the chat message |
| `support-reply` | a reply shown in the chat (one per reply) |
| `account-name` | text field for the name in the account form |
| `account-email` | text field for the email in the account form |
| `account-save` | button that saves the account |
| `account-success` | success message shown after the account is saved |

## Notes

- Every plan has its own page with its own URL (for example `/plans/<id>`); opening that URL directly, or reloading
  it, shows the same page.
- The account form shows the saved values again after a reload.
